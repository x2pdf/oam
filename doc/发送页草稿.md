# 发送页草稿

用户编辑消息过程中可能需要中断操作。草稿功能确保未发送的内容不会意外丢失，支持保存、恢复和管理。

日期：2026-08-22

## 功能范围

- **可保存为草稿的字段：** 文本内容、图片附件（含 base64 与文件名）、收件地址、加密开关。
- **不保存：** 密码输入、费用估算结果等临时 UI 状态。
- **触发时机：** 用户点击取消或系统返回（手势/物理返回键），且编辑区存在非空内容时弹出确认弹窗。
- **恢复时机：** 进入发送页时自动检测草稿，若存在则提示用户是否恢复。

## 使用流程

```
编辑消息中
    │
    ▼
点击取消 / 返回 ──► 弹窗「当前编辑内容尚未发送」
    │                      │
    │                      ├── ① 保存草稿 ──► 持久化到 AsyncStorage ──► 返回上一页
    │                      ├── ② 放弃编辑 ──► 二次确认弹窗 ──► 丢弃内容并返回
    │                      └── ③ 继续编辑 ──► 关闭弹窗，回到编辑状态
    │
    ▼
下次进入发送页 ──► 检测到草稿 ──► 提示「是否恢复上次未发送的草稿？」
    │                      │
    │                      ├── 恢复 ──► 填充所有字段
    │                      └── 丢弃 ──► 清除草稿，空白页面
```

### 核心交互规则

1. **保存草稿**：将当前所有编辑字段序列化后写入 AsyncStorage，Snackbar 提示「草稿已保存」，然后返回上一页。
2. **放弃编辑**：先弹窗二次确认「放弃后内容将无法恢复，确定要放弃吗？」，用户确认后才真正丢弃内容并返回。
3. **继续编辑**：关闭弹窗，用户留在当前编辑页面，不做任何操作。
4. **自动恢复**：进入发送页时若存在草稿，弹窗提示「检测到未发送的草稿（保存于 YYYY-MM-DD HH:mm），是否恢复？」，提供「恢复」与「丢弃」两个选项。
5. **发送成功清除**：消息成功发送后自动删除草稿。

## 数据模型

```ts
/** 图片附件的草稿快照 */
interface DraftImageItem {
  uri: string;
  base64: string;
  name?: string;
  type: 'image/jpeg' | 'image/png' | 'image/gif';
}

/** 发送页草稿 */
interface SendDraft {
  text: string;
  images: DraftImageItem[];
  recipientAddress: string;
  encryptEnabled: boolean;
  savedAt: number;       // Date.now()，草稿保存时间戳
}
```

草稿仅保存一份（覆盖式写入），不做多版本管理。每次保存覆盖上一条草稿。

存储键：`@oam_send_draft`（新增于 `src/constants/index.ts` 的 `STORAGE_KEYS.SEND_DRAFT`）。

## 状态与持久化

草稿读写直接在 `SendDataScreen` 内部通过 AsyncStorage 完成，不经过 `AppContext`。草稿属于页面级临时状态，无需全局共享。

| 操作 | 行为 |
| --- | --- |
| 保存草稿 | `AsyncStorage.setItem(STORAGE_KEYS.SEND_DRAFT, JSON.stringify(draft))` |
| 读取草稿 | `AsyncStorage.getItem(STORAGE_KEYS.SEND_DRAFT)` → 解析为 `SendDraft` |
| 清除草稿 | `AsyncStorage.removeItem(STORAGE_KEYS.SEND_DRAFT)` |

## 弹窗改造

### 现有取消弹窗（改造）

当前 `cancelConfirmVisible` 弹窗仅有两个选项（继续编辑 / 确认放弃）。改造为三个选项：

| 按钮 | 行为 |
| --- | --- |
| 保存草稿 | 序列化编辑状态 → 写入 AsyncStorage → Snackbar 提示 → `navigation.goBack()` |
| 放弃编辑 | 弹出二次确认弹窗（`discardConfirmVisible`） |
| 继续编辑 | 关闭弹窗 |

### 二次确认弹窗（新增）

`discardConfirmVisible`：标题「确认放弃」，内容「放弃后内容将无法恢复，确定要放弃吗？」。

| 按钮 | 行为 |
| --- | --- |
| 取消 | 关闭弹窗，回到三选项弹窗 |
| 确认放弃 | 清除草稿 → 清空编辑状态 → `navigation.goBack()` |

### 草稿恢复弹窗（新增）

`restoreDraftVisible`：进入发送页时若检测到草稿则弹出。标题「恢复草稿」，内容显示草稿保存时间和内容摘要。

| 按钮 | 行为 |
| --- | --- |
| 丢弃 | 清除 AsyncStorage 草稿 → 关闭弹窗 → 空白页面 |
| 恢复 | 将草稿字段填充到表单 → 关闭弹窗 |

## 界面说明

### 保存成功提示

使用现有 `Snackbar` 组件，显示「草稿已保存」，3 秒自动消失。

### 草稿恢复提示摘要

弹窗内容区显示：
- 保存时间（格式化）
- 文本内容前 50 字符预览
- 图片附件数量（如有）

## 注意事项

- 草稿保存在设备本地，换机、重装或清除应用数据后会丢失。
- 图片以 base64 编码存储在草稿中，大图片会占用较多存储空间；建议后续优化为文件引用方式。
- 草稿为单份覆盖式保存，不支持多版本管理。若需要历史草稿列表，可作为后续迭代方向。
- 发送成功后必须清除草稿，避免用户下次进入时看到已发送的旧内容。
- 收件地址为默认黑洞地址且文本和图片均为空时，不触发草稿保存弹窗，直接返回。
