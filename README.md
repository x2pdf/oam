# OAM (Onchain Attachment Message)
**以太坊链上附件消息数据互操作程序**

OAM 是一款专注于以太坊  `input data`  消息交互的开源工具。它实现了 **OAMP (Onchain Attachment Message Protocol)**，支持公开广播、个人加密笔记以及端到端加密通信，并提供富文本还原显示功能。

## 核心功能

### 1. OAMP 协议支持
基于以太坊交易 `input data` 的去中心化消息协议：
- **公开广播 (Broadcast)**：发送至零地址，全球可见。
- **加密个人笔记 (Personal Note)**：A → A 加密存储，仅发送者可解密。
- **端到端加密消息 (P2P Encrypted)**：基于 ECDH 共享密钥，仅指定接收者可解密。
- **明文点对点消息 (P2P Public)**：发送至指定地址，但内容不加密。

### 2. 富文本还原显示
识别 OAMP 格式数据并还原渲染：
- **代码块**：支持 `<pre>` 标签。
- **图片嵌入**：支持 `<img>` 标签还原。
- **图片选择**：支持从系统相册选取图片，并自动进行格式检查与 Base64 编码。
- **安全沙箱**：解析过程自动过滤恶意脚本，仅渲染白名单内的标签。

### 3. 数据互操作
- **多数据源集成**：动态支持 Etherscan 和 Blockscout API。
- **实时同步**：自动拉取订阅地址的链上消息流。
- **i18n 多语言**：支持中英文切换，适配全球用户。

### 4. 安全钱包管理
- **私钥存储**：使用 `expo-secure-store` 进行硬件级加密存储。
- **消息解密**：从钱包派生专用会话密钥，确保主私钥不直接参与消息加解密流程。

## 快速开始

### 1. 安装项目

```bash
git clone <project-url>
cd oam
npm install
```

> [!IMPORTANT]
> **随机数环境补丁**：
> 在 React Native 环境下，`ethers.js` 需要安全的随机数生成器。项目已集成 `react-native-get-random-values`。若你在新环境下运行报错 `platform does not support secure random numbers`，请确保已在入口文件 `index.js` 最顶部引入该库，并执行了原生模块安装。

### 2. 配置环境变量

在根目录创建 `.env` (或根据实际配置方式) 设置各区块浏览器的 API Key，以启用真实数据拉取。

### 3. 运行

```bash
# 启动开发服务器
npm start

# 运行到 iOS
npm run ios

# 运行到 Android
npm run android

# 运行 Web 端（浏览器访问 http://localhost:19006）
npm run web

# 构建 Web 生产版本（输出到 dist/ 目录）
npm run build:web
```

## 协议细节 (OAMP)

所有消息遵循以下 Envelope 格式：
`MAGIC (4 bytes: "OAMP") | VERSION (1 byte) | TYPE (1 byte) | CRYPTO (1 byte) | NONCE (12 bytes) | PAYLOAD (n bytes)`

- **TYPE**: `0` 广播, `1` 个人, `2` P2P
- **CRYPTO**: `0` 无, `1` AES-256-GCM

详细文档请参考 [src/oamp/README.md](src/oamp/README.md)。

- **激励机制设计**：为 OAM 生态引入可持续的激励体系，初步方向包括：① 链上打赏——读者可直接向优质公开广播的作者地址打赏 ETH，形成内容价值正反馈；② 链上声誉——基于发送量、被引用次数等行为数据为每个地址构建不可篡改的信誉积分；③ 成就徽章——为首次发送、百条里程碑等关键节点颁发 POAP 风格的链上 NFT 凭证；④ 积分系统——活跃度产生的链下积分可于未来兑换为治理权益或高级功能使用权，为后续通证经济留出接口。
- **发送页草稿功能**：在发送页引入草稿自动保存与恢复机制。用户编辑消息内容（文本、图片、收件地址、加密选项等）时，系统自动将当前编辑状态持久化为草稿；当用户点击取消或返回时，弹窗提供三项选择：① 保存草稿并返回；② 放弃编辑（二次确认后丢弃）；③ 继续编辑。下次进入发送页时自动检测并提示恢复未发送的草稿。
- **发送附带 ETH 转账**：允许在发送 OAMP 消息时附带非零 ETH 金额（仅支持原生 ETH，不涉及 ERC-20）。金额输入框默认锁定，用户须通过支付密码验证后方可编辑，防止误操作。提供 MAX 按钮一键填入「余额 − 预估 Gas」的最大可转金额。核心场景：用户希望弃用 OAM 钱包时可直接在应用内清空余额至外部地址，无需借助第三方钱包。
- **用户间交互（点赞与热门排行）**：当前 OAM 消息为单向平铺广播，用户之间无法产生互动。初步方案：部署轻量链上状态计数器合约，以消息的交易哈希（input data ID）为主键，支持对任意 OAM 消息进行点赞 / 取消点赞，并维护每条消息的累计点赞数；客户端按一定时间窗口（如 24h / 7d）聚合链上点赞事件，生成全局热门消息排行榜，使用户能够快速发现社区高价值内容。
- **Gas 费多档位与自定义**：当前手续费估算仅使用 RPC 节点返回的默认 `maxFeePerGas`（相当于固定"标准速度"），缺乏灵活度。计划增加多档位速度选择（如慢 / 标准 / 快），对应不同的 `maxPriorityFeePerGas` 加成；同时提供手动编辑入口，允许高级用户直接修改 `maxFeePerGas`、`maxPriorityFeePerGas` 和 `gasLimit` 等参数，以满足紧急上链或低成本排队等不同场景需求。
- **关注列表导入与导出**：为关注列表（Subscriptions）增加数据导入 / 导出功能，便于用户跨设备迁移、备份及共享订阅数据。核心设计要点：① **格式设计**——采用 JSON 作为导出文件格式，顶层包含版本号（`version`）和导出时间戳（`exportedAt`），数据体为 `Subscription[]` 数组，每个条目保留 `address`、`description`、`chain`、`walletType`、`pinWeight` 等完整字段，确保人类可读且便于第三方工具解析；② **去重策略**——导入时以 `address`（不区分大小写）为主键进行去重，对已存在的地址跳过导入或提示用户选择覆盖 / 跳过 / 合并，避免重复条目；③ **兼容性**——导入解析器需向后兼容旧版字段缺失情况（如无 `chain` 或 `pinWeight` 字段时自动填充默认值），导出文件标注版本号以便未来格式演进时做迁移适配；④ **交互流程**——导出通过系统分享面板生成 `.json` 文件，导入支持从文件系统选取 `.json` 文件并在预览界面展示待导入条目数量及去重结果，确认后再执行写入。
- **广场数据本地缓存与离线浏览**：当前广场页每次进入均需从远程数据源实时拉取链上交易数据，无本地缓存机制，导致重复加载耗时长且无法离线使用。计划引入本地缓存层：① 自动缓存——每次拉取成功后将结果持久化到本地，再次进入时优先展示缓存数据并在后台静默刷新；② 日期区间批量下载——允许用户指定起止日期，将该区间内的所有链上消息完整下载并归档存储，便于历史回溯与离线浏览；③ 存储格式待论证——需综合评估按天分片（直觉友好但单日数据量波动大）、按区块范围分片（链上原生粒度但用户不直观）、按地址 + 时间索引（便于按订阅维度查询）等方案的优劣，最终确定兼顾查询效率与存储可控性的本地数据结构。
- **数据支持导出的初步设想**：可以支持导出数据，以csv 形式导出，导出字段待定，在那些位置可以有这个功能待定，导出时间范围待定，导出时是以原文导出还是解密以后导出待定。

- **多屏适配与桌面 UI 优化**：当前仅在桌面横屏时对列表卡片做了简单的居中 50% 宽度处理（`useListColumnLayout`），尚未针对不同设备形态做系统化的 UI 适配。计划从以下方向优化：① **折叠屏适配**——检测折叠 / 展开状态变化，在展开态利用大屏空间采用双栏或多列布局（如左侧关注列表 + 右侧消息流），折叠态回退为单栏手机布局，确保过渡动画流畅且状态不丢失；② **平板适配**——根据屏幕宽度断点（如 ≥ 600px / ≥ 900px）自动切换紧凑 / 标准 / 宽松布局，卡片间距与字号随尺寸梯度调整；③ **桌面深度优化**——将底部 Tab 导航升级为左侧固定侧边栏，支持键盘快捷键操作（如 ↑↓ 切换条目、Enter 打开详情），利用桌面端宽屏空间展示更多信息列（发送方、时间戳、Gas 消耗等），并适配窗口自由缩放时的响应式重排。
